# Отчет о реализации алгоритма сжатия

## Выполненное задание

### 1. Самостоятельная реализация алгоритма сжатия ✅

**Алгоритм:** LZ77 (основа DEFLATE/GZIP)

**Файлы реализации:**
- `LZ77.kt` - алгоритм LZ77 (самостоятельная реализация)
- `Huffman.kt` - фиксированные Huffman коды для DEFLATE (RFC 1951)
- `Deflate.kt` - DEFLATE формат (LZ77 + Huffman кодирование, полностью самостоятельная реализация)
- `Crc32.kt` - вычисление CRC32 для GZIP (самостоятельная реализация)
- `GzipFormat.kt` - GZIP формат (RFC 1952, полностью самостоятельная реализация без Java библиотек)
- `BitWriter.kt` / `BitReader.kt` - работа с битами (LSB first для DEFLATE)
- `LZ77Encoder.kt` - кастомный бинарный формат для LZ77 токенов

**Как работает LZ77:**
1. Ищет повторяющиеся последовательности в уже обработанных данных
2. Заменяет их ссылками (offset, length)
3. Окно поиска: 32KB
4. Минимальная длина совпадения: 3 байта
5. Максимальная длина: 258 байт

**Пример:**
```
Исходные данные: "ABCABCABC"
LZ77 токены: [Literal('A'), Literal('B'), Literal('C'), Reference(offset=3, length=6)]
```

### 2. Реализация формата хранения для нашего алгоритма ✅

**Кастомный бинарный формат (LZ77Encoder):**
- 4 байта: размер исходных данных (little-endian)
- Для каждого токена:
  - Literal: `0x00` + 1 байт (значение байта)
  - Reference: `0x01` + 2 байта offset (little-endian) + 2 байта length (little-endian)

**Это наш собственный формат** для сериализации LZ77 токенов в бинарный вид.

**Совместимость с GZIP:**
- `GzipFormat.kt` - **полностью самостоятельная реализация** GZIP формата (RFC 1952)
  - Реализован DEFLATE (LZ77 + фиксированные Huffman коды) согласно RFC 1951
  - Реализован GZIP заголовок, CRC32, размер исходных данных
  - **Не использует Java библиотеки** (`java.util.zip.*`)
- ✅ Можно распаковать через `gunzip`
- ✅ Можно распаковать через `7z`
- ✅ Можно распаковать через Java `GZIPInputStream`
- **Примечание:** GZIP формат используется для демонстрации совместимости с внешними утилитами, но в базе данных используется наш кастомный формат (`CustomCompressionFormat`)

### 4. Интеграция в базу данных ✅

**Файл:** `Codec.kt`

**Как работает:**
- **Метаданные** (id, tombstone, compressed флаг) остаются в **человекочитаемом JSON**
- **Данные (payload)** сжимаются нашим кастомным кодером (`CustomCompressionFormat`)
- Payload (JSON строка Row) > 50 байт → автоматически сжимается нашим LZ77 алгоритмом
- Сжатые данные кодируются в Base64 для хранения в JSON поле `payload`
- Флаг `compressed: true` в `RecordLine` указывает, что payload сжат
- При чтении автоматически распаковывается нашим декодером

**Архитектура:**
```
INSERT:
  Row (объект) → JSON сериализация → payload (JSON строка)
    → если payload > 50 байт → CustomCompressionFormat.compress()
      → LZ77.compress() → токены (Literal/Reference)
      → LZ77Encoder.encode() → бинарный формат (наш формат)
      → Base64.encode() → JSON поле "payload"
      → RecordLine (JSON) → файл .tbl
  
SELECT:
  Файл .tbl → JSON строка RecordLine
    → если "compressed": true → Base64.decode()
      → CustomCompressionFormat.decompress()
        → LZ77Encoder.decode() → токены
        → LZ77.decompress() → исходный payload (JSON строка)
        → JSON десериализация → Row (объект)
```

**Важно:** 
- Используется **наш собственный алгоритм** (LZ77) и **наш собственный формат** (LZ77Encoder)
- Метаданные остаются читаемыми в JSON
- Данные сжимаются только если payload > 50 байт
- **GzipFormat НЕ используется в базе данных** - он только для демонстрации совместимости с gunzip

## Демонстрация совместимости с gunzip

**Создание GZIP файла:**
```kotlin
val data = "Test data".toByteArray()
val compressed = GzipFormat.compress(data)
File("test.gz").writeBytes(compressed)
```

**Распаковка через gunzip:**
```bash
gunzip -c test.gz
# или
zcat test.gz
```
